# 디자인 스타일 라이브러리: 웹 20종 + PPT 20종 + 인포그래픽 20종 (HTML 네이티브 우선)

> **2026-06 재구성**. 글로벌 10대 웹사이트 유형 + 10대 프레젠테이션 유형, 각 top5 공인 베스트 디자인(총 100개 실제 사례)에 대한 조사 및 역추적 기반.
> 구버전 20종 「평면/설치 디자이너 철학」 라이브러리의 치명적인 문제: 대담한 스타일은 거의 모두 AI-생성-only(파티클/광원/핸드드로잉)였으며, **사용자가 기본적으로 이미지 생성 능력이 없고 default가 모두 HTML로 진행될 때, 대담한 스타일의 절반이 즉시 사라지고 미니멀리즘만 남게 됨 — 이것이 「default 천편일률」의 근본 원인**. 본 라이브러리는 각 스타일마다 「이미지 생성 없는 순수 HTML/CSS」 환경에서의 **재현도**를 표기함.
>
> ⚖️ **하지만 포지셔닝을 기억하세요**: 이것은 **「아이디어가 없을 때 찾아보는 탄약」이지, 「반드시 여기서 골라야 하는」 체크리스트가 아닙니다**. 사용자가 콘텐츠/브랜드/참고 자료를 제공했다면 디자인은 거기서부터 시작되어야 하며, 라이브러리를 그대로 끼워 맞추지 마세요. skill의 역할은 사용자가 최악을 피하도록 돕는 것이지, 디자인이 어떻게 생겨야 하는지 규정하는 것이 아닙니다 — 좋은 디자인은 사용자의 실제 요구 사항에서 나옵니다.

## 이 라이브러리 사용법

1. **먼저 출력 유형에 따라 섹션을 선택하세요 (2택 1이 아닌 3택 1)**: 웹페이지/랜딩 페이지/공식 사이트 제작 → 웹 20종; PPT/deck/프레젠테이션 제작 → PPT 20종; 인포그래픽/데이터 시각화/단일 롱 이미지 제작 → 인포그래픽 20종.
   - 판단 기준은 **소재가 아닌 결과물 형태**입니다: 클릭 가능한 사이트는 웹 섹션, 페이지를 넘겨야 하는 것은 PPT 섹션, **데이터가 주인공이며 인터랙션 없이 독립적으로 읽을 수 있는 한 장(또는 한 세트)의 이미지는 인포그래픽 섹션**으로 분류합니다.
   - 판단이 모호한 두 가지 일반적인 경우: Dashboard 프로토타입은 웹 섹션(제품 인터페이스임); 한 페이지의 deck에 삽입된 데이터 페이지는 여전히 PPT 섹션(페이지를 넘겨야 함).
2. **온도 체계**: 각 스타일마다 `대담 / 중성 / 차분`이 표기되어 있습니다. **의도적으로 대담한 스타일이 다수를 차지하도록 구성**했습니다 — 모델의 확정성 편향은 본래 차분하고 미니멀한 쪽으로 치우치기 때문에, 라이브러리 비율을 통해 대담한 쪽으로 밀어붙여야 합니다.
   - 방향 A (안정적인 기반)는 차분함/중립 중에서 필요에 따라 선택; 방향 B는 서로 다른 온도를 취해 대비를 줌; **방향 C는 SKILL의 「초 단위 룰렛」에 의해 대담한 스타일을 강제로 주입**.
   - ❌ 세 가지 방향 모두 「아이보리 + 여백 + 하나의 강조색」으로 결정하지 마세요 — 그것은 가장 흔한 실패 패턴입니다.
3. **재현도**: ≥90% 고민 없이 실행; 70-90% 본체는 가능하나 일부 디테일은 하향 조정; <70% (예: Memphis 빈티지 질감)는 결과물에 **어느 부분이 단색 블록으로 하향 조정되었는지 명확히 표기**해야 하며, 원본의 질감을 구현할 수 있는 척하지 마세요.
4. **폰트**: 각 스타일마다 오픈 소스 대체 폰트(Inter/Geist/Manrope/Space Grotesk/Fraunces/Playfair 등)를 제공하며, 유료 폰트(Söhne/Circular 등)는 작성하지 마세요.
5. 연계: SKILL 「디자인 방향 컨설턴트」 Phase 3-5에서 본 라이브러리를 사용해 3가지 방향을 제시; `assets/showcases/`에 사전 제작된 스크린샷 갤러리가 있음.

## 색상 도출 프로토콜 (어떤 스타일을 사용하기 전에 먼저 이 세 단계를 거치세요)

> ⚠️ **아래 모든 스타일 항목의 hex 값은 예시 앵커일 뿐, 레시피가 아닙니다.** 동일한 스타일이 다른 콘텐츠에 사용될 때는 본 프로토콜을 통해 서로 다른 색상 값을 도출해야 합니다 — 항목의 hex를 그대로 복사하는 것은 단순히 미적 감각이 조금 더 나은 slop을 생산하는 것일 뿐입니다. 이유: 레시피를 고정하면 100명의 사용자가 100개의 동일한 색상 결과물을 받게 되어 색상의 정보량이 0이 됩니다. 도출 과정을 거쳐야 색상이 「이콘텐츠만의 고유한」 증거가 됩니다.
>
> **폰트도 마찬가지입니다**: 항목의 폰트 이름 또한 예시 앵커입니다. 스타일을 선택한 후, display+body 조합은 먼저 `references/typography.md`의 조합 로직과 「이미 너무 많이 쓰인 명단」을 거쳐야 합니다 — **명단과 항목이 충돌할 경우 typography.md를 기준으로 합니다** (예: 항목에 Fraunces라고 적혀 있어도 명단에 따라 Newsreader 등 대체 폰트로 교체).

### 3단계 프로세스: 샘플링 → 수렴 → 논증

| 단계 | 수행 작업 | 이유 |
|------|--------|--------|
| **1. 샘플링** | 주색은 세 가지 소스에서 가져오며, 허공에서 발명하지 않습니다: ①브랜드 자산 (logo/기존 VI에서 직접 추출) ②콘텐츠 실사 이미지 (제품 스크린샷/사진 소재의 주도색) ③문화적 맥락 (콘텐츠 주제가 자체적으로 가진 색상 기억, 아래 표 참조) | 근거 없이 색상을 선택하는 것은 모델의 선험적 지식에서 제비뽑기를 하는 것과 같아 항상 뻔한 인기 색상만 나옵니다. 콘텐츠에서 추출한 색상은 자연스럽게 「이유」를 갖게 됩니다. |
| **2. 수렴** | oklch를 사용하여 팔레트를 **2-3개의 유채색 + 1개의 중성색 그룹**으로 압축합니다. 중성색은 명도 시퀀스(예: L 0.15/0.35/0.65/0.92/0.98)로 작성하고, 유채색 사이에는 oklch 색상각 H ≥60° 또는 명도 L 차이 ≥0.3을 둡니다. | 색이 많으면 반드시 혼란스러워집니다. oklch의 L 채널은 지각적으로 균일하여, 명도 시퀀스를 작성하면 고립된 hex 값들보다 추론 가능한 계층 시스템이 됩니다. |
| **3. 논증** | 「왜 이 색인가」를 한 문장으로 작성하여 결과물 주석이나 인도 설명서에 기입합니다. 예: 「주색은 사용자 로고의 황토색에서 가져왔으며, chroma를 0.08로 낮추어 잉크를 모방함」 | **이 문장을 쓸 수 없다면 = 레시피를 베끼고 있는 것입니다.** 논증은 slop(조잡한 결과물)을 방지하는 자가 점검 도구이지, 의식이 아닙니다. |

### 인쇄색 질감: 왜 저채도가 순수 스크린색보다 고급스러운가

잉크가 종이에 인쇄될 때는 스크린 RGB의 최대 채도에 도달할 수 없습니다. CMYK 색역이 더 좁고, 종이의 잉크 흡수, 주변광 반사 등이 모두 색을 「탁하게(압축된 회색)」 만듭니다. 수십 년 동안 인쇄물에 의해 훈련된 인간 눈의 「고급스러움」은 본질적으로 이 물리적인 회색 층에 있습니다. 따라서 스크린 디자인에서 의도적으로 chroma를 낮추는 것은 인쇄의 질감 기억을 빌려오는 것과 같습니다.

| 용도 | oklch chroma 참고 | 효과 |
|------|------------------|------|
| 대면적 배경색 | 0.01–0.04 | 종이 질감, 눈의 피로 적음 |
| 브랜드 주색/강조 | 0.08–0.15 | 잉크 질감, 충분히 눈에 띄지만 플라스틱 느낌이 없음 |
| 소면적 포인트(버튼/링크) | 0.15–0.22 | 활력을 유지하되, 소면적에만 한정 |
| >0.25 전체 배경 | 주의 사용 | 스크린 형광 느낌, Wrapped/캔디와 같은 의도적인 「디지털 네이티브」 스타일에만 적합 |

### 문화적 맥락 퀵 체크: 동일한 색상, 다른 맥락

색을 선택하는 것은 단순히 색상을 고르는 것이 아니라, 그 뒤에 숨겨진 문화적 좌표를 선택하는 것입니다. 같은 「빨강」이라도 결과는 천차만별입니다:

| 색상 | 맥락 A | 맥락 B | 차이점 |
|------|--------|--------|--------|
| 빨강 | 고궁 주홍(오렌지빛, 회색빛 포함, oklch 낮은 L 낮은 C, 콜라 레드보다 어둡고 탁함) → 전통/장중함 | 콜라 레드(고채도 정석 빨강) → 소비/흥분 | chroma가 낮아지면, 진열대에서 궁궐 담장으로 이동합니다 |
| 파랑 | 일본 아이조메/루리콘(진하고 보랏빛 회색) → 수공예/차분함 | 테크 블루 #0066FF 계열 → SaaS/효율 | 후자는 모델이 가장 선호하는 기본 파랑입니다. 사용하기 전에 스스로 운에 맡기고 있는 것은 아닌지 물어보세요 |
| 초록 | 말차/이끼 녹색(노란빛, 저채도) → 자연/일본풍 | 형광 녹색 #39FF14 → 터미널/해커 | 같은 초록이라도 하나는 차를 마시고 하나는 코딩을 합니다 |
| 노랑 | 등황/머스터드(갈색빛 회색 포함) → 레트로 인쇄 | 경고 노랑/Mailchimp 옐로우 → 눈에 띔/위트 | 회색도가 그것이 오래된 책장인지 안전모인지를 결정합니다 |
| 하양 | 크림 페이퍼 화이트 #F5F0E8 → 출판물/따뜻함 | 순백 #FFF → 실험실/스위스 | 배경색의 2% 색온도 차이가 분위기의 갈림길입니다 |

## 웹 스타일 라이브러리(20종)

#### 대담파

**미디어급 브루탈리즘 Editorial Brutalism（거대한 Helvetica가 작은 본문을 압도）** `대담·재현98%`
- 참고:Bloomberg Businessweek（Richard Turley 2010–2014 개편，Code and Theory 담당）；Neue Haas Grotesk 계열
- 적용 대상:미디어/콘텐츠 출판、AI 제품 발표、브랜드 홈페이지 hero、리서치 보고서 표지、의견형 장문 헤더 이미지
- 시각 DNA: 배색=순수 검정#000+순백#FFF+링크 블루#0000EE, 신호 오렌지레드#FF433D/터미널 그린#00A33E를 포인트로 사용. 서체=Helvetica/Neue Haas Grotesk, 120px+ 대형 headline을 왼쪽 정렬·촘촘한 자간으로 14px 작은 본문 위에 강하게 배치해 극단적 크기 대비를 만든다. 레이아웃=모듈형 그리드+1px 규칙선으로 칼럼을 분할하고, 높은 정보 밀도를 위해 의도적으로 여백을 남기지 않는다. 표지 요소=규칙선 칼럼, 링크 블루 밑줄, 흑백 바탕의 큰 색 블록.
- HTML 구현: 순수 CSS로 1:1 재현 가능. CSS Grid로 모듈형 그리드를 구성하고 border로 규칙선 칼럼을 나눈다. clamp()로 초대형 반응형 글자 크기를 만들고 letter-spacing을 좁히며, 시스템 Helvetica/Arial 스택 또는 Inter를 폴백으로 사용한다. 하이퍼링크에는 #0000EE 밑줄을 직접 적용한다. 외부 소재에 의존하지 않는다.
- 글꼴: Inter(Helvetica/Neue Haas Grotesk 대체), 코드에는 Geist Mono 사용

**신 브루탈리즘 충돌색 정보 피드 Neo-Brutalism（두꺼운 검은 아웃라인 카드+고채도 충돌색）** `대담·재현95%`
- 참고: The Verge 2022 리디자인(in-house team, PolySans + Mānuka)
- 적용 대상: 미디어/콘텐츠 사이트, AI 제품 모음 페이지, 이벤트 landing, 커뮤니티 순위 페이지, Xiaohongshu풍 정보 카드
- 시각 DNA: 배색=일렉트릭 퍼플#5200FF~마젠타#E1306C의 고채도 주색+밝은 노랑#F8E000 강조색+순수 검정#08080D+흰색. 넓은 대비 색 블록을 의도적으로 부드럽게 다루지 않는다. 서체=기하학적 산세리프 대형 제목과 세리프 본문의 대비. 레이아웃=카드형 feed 흐름, 2-4px 굵은 검정 윤곽선, 단단한 색 블록 구획, 거의 없는 둥근 모서리. 표지 요소=굵은 윤곽선 카드의 hover 대비색 반전, 미완성 인터페이스 분위기.
- HTML 구현: 순수 CSS의 강점이 잘 드러난다. border:3px solid #000 굵은 윤곽선+box-shadow의 단단한 오프셋 그림자(4px 4px 0 #000)+grid/flex 카드 흐름+:hover에서 background를 바꿔 대비색 반전을 구현한다. 3D나 광원 효과가 필요 없다.
- 글꼴:Space Grotesk（PolySans 대체）+ 임의의 세리프（예: Fraunces）

**멤피스 복고 콜라주 극대화 Memphis Maximalism（대비 색 블록+어긋나게 겹치기+복고 서체）** `대담·재현72%`

## ⚠️ AI 이미지 생성 전용 스타일 (사용자의 이미지 생성 능력이 확인된 경우에만 추천, default 선택 불가)

아래 스타일의 핵심은 **동적 생성 비주얼 / 3D / 파티클 / 시네마틱 조명 / 핸드 드로잉 일러스트**이며, 이미지 생성 없이 순수 HTML/CSS만으로는 품질이 현저히 낮은 mock만 만들 수 있으므로 **default 추천 풀에서 제외**합니다. 사용자가 명확히 이미지 생성 능력을 갖춘 경우(`design-gpt-image` 사용) 시에만 후보로 고려합니다:

| 스타일 | 핵심 | HTML로 구현 불가능한 이유 |
|------|------|------------------|
| Active Theory (WebGL 파티클) | 3D 파티클 시스템/실시간 렌더링 | 순수 CSS로는 불가능 |
| Field.io (제너레이티브 아트) | 알고리즘 생성 그래픽 | 정적 SVG로는 경직되고 단순화된 버전만 가능 |
| Resn (일러스트레이션 인터랙션) | 캐릭터 일러스트+게이미피케이션 | 핸드 드로잉 소재에 의존 |
| Zach Lieberman (실시간 생성) | creative coding 터치(Stroke) | 실시간 생성에 의존 |
| Raven Kwok (프랙탈 파라미터) | 재귀적 프랙탈 | CSS로는 복잡도 구현 불가 |

## 기본 미학 금지 구역 (사용자는 브랜드에 따라 override 가능)

- ❌ **GitHub-dark 게으른 해결책**: 균일한 짙은 파란색 배경(#0D1117) + 범용 청색/보라색 네온 glow —— 흔해 빠진 이 조합만 금지하며, '모든 어두운 색 금지'가 아닙니다.
- ✅ **금지 구역 아님**: 영화급 드라마틱한 광원, 따뜻한 색감의 사이버(Ash Thorp 오렌지/청록), 스포츠 시학의 어두운 서사 —— 제작자의 의도가 담긴 어두운 색은 유지(본 라이브러리의 「Linear 다크 발광」, 「검은 배경 디지털 극장」, 「CS50 캔디 스테이지」는 허용된 어두운 색입니다)
- ❌ 급진적인 보라색 그라데이션 만능 공식, emoji를 아이콘으로 사용, 둥근 모서리 카드 + 왼쪽 컬러 border accent (브랜드 자체에서 사용하는 경우 제외)
- ❌ 표지 이미지에 개인 서명/워터마크 추가

## 이미지 생성 능력이 있을 때의 프롬프트 비법 (Mood, Not Layout)

> AI 이미지 생성 경로를 이용할 때만 적용됩니다. HTML 경로는 위의 각 스타일별 「HTML 구현」에 따라 직접 코드를 작성하세요.

짧은 프롬프트 > 긴 프롬프트. 30줄의 레이아웃 세부 사항을 쌓는 것보다 감정과 내용을 묘사하는 것이 더 효과적입니다.

| 다양성을 죽이는 작성법 | 창의성을 자극하는 작성법 |
|----------------|----------------|
| 색상 비율 지정 (60%/25%/15%) | 감정 묘사 ("warm like Sunday morning") |
| 레이아웃 위치 규정 | 구체적인 미학 인용 ("Pentagram editorial feel") |
| 모든 시각적 요소 나열 | 관객이 무엇을 느껴야 하는지 묘사 |

전체 AI 이미지 생성 방법론 → `design-gpt-image` skill.
