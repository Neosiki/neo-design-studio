# 핵심 자산 프로토콜 (전체판)

> SKILL.md「핵심 철학 #1.a」에서 내려온 전체 프로토콜(2026-06 다이어트). SKILL.md에는 발동 조건 + 5단계 제목 + 자기점검만 남겼고, 여기에는 5단계 상세 절차, 다운로드 명령, brand-spec 템플릿, 전 과정 실패 시 방어선, 반례와 비용 비교가 있다.
> 발동: 작업이 구체적 브랜드/제품과 얽히면 강제 실행. 축약판과 맥락은 SKILL.md에서 보세요.

#### 1.a 핵심 자산 프로토콜 (구체적 브랜드가 얽히면 강제 실행)

> **v1에서 가장 핵심적인 제약이자 안정성의 생명선이다.** Agent가 이 프로토콜을 제대로 통과하는지가 출력 품질을 40점으로 만들지 90점으로 만들지를 곧바로 결정한다. 어느 단계도 건너뛰지 말 것.
>
> **v1.1 재구성(2026-04-20)**: 「브랜드 자산 프로토콜」에서 「핵심 자산 프로토콜」로 승격했다. 이전 판은 색값과 글꼴에 과도하게 쏠려서 디자인의 가장 기초인 logo / 제품 사진 / UI 스크린샷을 놓쳤다. Neo의 원문: 「이른바 브랜드 색 말고도, 당연히 DJI의 logo를 찾아서 써야 하고 pocket4의 제품 사진을 써야 한다. 웹사이트나 앱처럼 실체가 없는 제품이라면 logo만이라도 반드시 있어야 한다. 이게 이른바 브랜드 디자인 spec보다 더 중요한 기본 논리일 것이다. 그러지 않으면 우리는 대체 무엇을 표현하고 있는 건가?」

**발동 조건**: 작업이 구체적 브랜드와 얽힐 때 — 사용자가 제품명/회사명/명확한 고객사를 언급했을 때(Stripe, Linear, Anthropic, Notion, Lovart, DJI, 자사 등). 사용자가 브랜드 자료를 먼저 줬는지 여부와 무관하다.

**선행 하드 조건**: 프로토콜에 들어가기 전에 「#0 사실 검증이 가정보다 먼저」를 통과해 브랜드/제품이 존재하고 상태가 파악됐음을 확인해야 한다. 제품이 출시됐는지, 규격이나 버전이 어떤지 아직 확실치 않다면 먼저 돌아가서 검색한다.

##### 핵심 이념: 자산 > 규범

**브랜드의 본질은 「알아보게 되는 것」이다.** 무엇으로 알아보는가? 식별도 순으로 정렬하면 이렇다.

| 자산 유형 | 식별도 기여 | 필수성 |
|---|---|---|
| **Logo** | 최고 · 어떤 브랜드든 logo가 나오면 한눈에 식별된다 | **어떤 브랜드에도 반드시 있어야 한다** |
| **제품 사진/제품 렌더링** | 매우 높음 · 실물 제품의 "주인공"은 제품 자체다 | **실물 제품(하드웨어/패키지/소비재)은 반드시 있어야 한다** |
| **UI 스크린샷/화면 소재** | 매우 높음 · 디지털 제품의 "주인공"은 그 화면이다 | **디지털 제품(App/웹사이트/SaaS)은 반드시 있어야 한다** |
| **색값** | 중 · 보조 식별. 앞의 셋이 없으면 자주 남과 겹친다 | 보조 |
| **글꼴** | 낮음 · 앞의 것들과 함께여야 식별이 세워진다 | 보조 |
| **기질 키워드** | 낮음 · agent 자기점검용 | 보조 |

**실행 규칙으로 옮기면**:
- 색값 + 글꼴만 뽑고 logo / 제품 사진 / UI를 찾지 않음 → **본 프로토콜 위반**
- CSS 실루엣이나 손으로 그린 SVG로 실제 제품 사진을 대체 → **본 프로토콜 위반**(그렇게 나오는 건 「일반 테크 애니메이션」이고, 어느 브랜드든 똑같이 생긴다)
- 자산을 못 찾았는데 사용자에게 알리지도, AI로 생성하지도 않고 억지로 진행 → **본 프로토콜 위반**
- 멈춰서 사용자에게 소재를 요청하는 편이 낫다. generic으로 채우지 말 것

##### 5단계 하드 절차 (단계마다 fallback이 있고, 조용히 건너뛰는 일은 절대 없다)

##### Step 1 · 묻기 (자산 목록을 한 번에 전부 묻는다)

「brand guidelines 있으세요?」만 묻지 말 것 — 너무 넓어서 사용자가 무엇을 줘야 할지 모른다. 목록으로 항목마다 묻는다.```
<brand/product> 관련해서 아래 중 어떤 자료를 갖고 계신가요? 우선순위대로 적습니다.
1. Logo(SVG / 고해상 PNG) —— 어떤 브랜드에도 필수
2. 제품 사진 / 공식 렌더링 —— 실물 제품이면 필수(예: DJI Pocket 4 제품 사진)
3. UI 스크린샷 / 화면 소재 —— 디지털 제품이면 필수(예: App 주요 화면 스크린샷)
4. 색값 목록(HEX / RGB / 브랜드 색판)
5. 글꼴 목록(Display / Body)
6. Brand guidelines PDF / Figma design system / 브랜드 공식 사이트 링크

있는 건 그대로 보내주시고, 없는 건 제가 검색·수집·생성하겠습니다.
```

##### Step 2 · 공식 채널 검색 (자산 유형별)

| 자산 | 검색 경로 |
|---|---|
| **Logo** | `<brand>.com/brand` · `<brand>.com/press` · `<brand>.com/press-kit` · `brand.<brand>.com` · 공식 사이트 header의 inline SVG |
| **제품 사진/렌더링** | `<brand>.com/<product>` 제품 상세 페이지의 hero image + gallery · 공식 YouTube launch film 프레임 캡처 · 공식 보도자료 첨부 이미지 |
| **UI 스크린샷** | App Store / Google Play 제품 페이지 스크린샷 · 공식 사이트 screenshots section · 제품 공식 데모 영상 프레임 캡처 |
| **색값** | 공식 사이트 inline CSS / Tailwind config / brand guidelines PDF |
| **글꼴** | 공식 사이트 `<link rel="stylesheet">` 참조 · Google Fonts 추적 · brand guidelines |

`WebSearch` 방어선 키워드:
- Logo를 못 찾으면 → `<brand> logo download SVG`, `<brand> press kit`
- 제품 사진을 못 찾으면 → `<brand> <product> official renders`, `<brand> <product> product photography`
- UI를 못 찾으면 → `<brand> app screenshots`, `<brand> dashboard UI`

##### Step 3 · 자산 다운로드 · 유형별 3중 방어 경로

**3.1 Logo (어떤 브랜드에도 필수)**

> ⚠️ **`curl <brand>.com/logo.svg` 한 번 해보고 포기하지 말 것** — 요즘 공식 사이트는 대부분 SPA라서 정적 경로로 직접 붙으면 거의 빈 껍데기 HTML이 돌아온다(2026-06-06 실측: Trae 공식 사이트 직접 경로 5개 전부 빈 껍데기). **디지털 제품 / SaaS / AI 도구는 아이콘 취합 소스를 우선**한다. 적중률이 가장 높고 깨끗한 SVG가 바로 나온다.

성공률 내림차순으로:
0. **아이콘 취합 소스(유명 디지털 제품/SaaS/AI 도구는 1순위, 적중률 최고)**:
   ```bash
   unset ALL_PROXY HTTP_PROXY HTTPS_PROXY all_proxy http_proxy https_proxy   # 프록시를 지운다. 안 그러면 TLS가 쉽게 터진다
   # svgl —— AI/개발자 브랜드 커버리지가 가장 넓다(Claude/Cursor/OpenAI/Copilot/Anthropic/Vercel…). light/dark + wordmark 포함
   curl -s "https://api.svgl.app?search=<brand>"   # JSON이 돌아온다. route(.light/.dark)의 svg URL을 꺼내 다시 다운로드
   # simpleicons —— 단색 glyph. 브랜드 색으로 바로 칠할 수 있다
   curl -o logo.svg "https://cdn.simpleicons.org/<slug>/<hexcolor>"
   ```
1. 독립 SVG/PNG 파일 / 공식 brand 페이지(예: `<brand>.com/brand`, `/press`):
   ```bash
   curl -A "Mozilla/5.0" -L -o assets/<brand>-brand/logo.svg "<official-logo-url>"
   ```
2. 공식 사이트 HTML 전문에서 inline SVG 추출:
   ```bash
   curl -A "Mozilla/5.0" -L https://<brand>.com -o assets/<brand>-brand/homepage.html
   # 그 다음 grep으로 <svg>...</svg> logo 노드를 추출한다
   ```
3. **Google favicon 서비스(사이트의 실제 mark 방어선. 거의 실패하지 않는다)**:
   ```bash
   curl -o logo.png "https://www.google.com/s2/favicons?domain=<brand-domain>&sz=256"   # 256px 공식 사이트 아이콘
   ```
4. 공식 소셜 미디어 avatar(마지막 수단): GitHub/Twitter/LinkedIn의 회사 프로필 사진은 보통 400×400이나 800×800 투명 배경 PNG다

다운로드한 뒤 **하나씩 대조한다**: `file <logo>`로 진짜 SVG/PNG인지 확인(106바이트 자리표시자나 빈 껍데기 HTML이 아닌지), `head -c 90 <logo.svg>`로 `<svg`로 시작하는지 확인.

**3.2 제품 사진/렌더링 (실물 제품 필수)**

우선순위대로:
1. **공식 제품 페이지 hero image**(최우선): 우클릭으로 이미지 주소 보기 / curl로 받기. 해상도는 보통 2000px 이상
2. **공식 press kit**: `<brand>.com/press`에 고해상 제품 사진 다운로드가 자주 있다
3. **공식 launch video 프레임 캡처**: `yt-dlp`로 YouTube 영상을 받고 ffmpeg으로 고해상 프레임 몇 장을 뽑는다
4. **Wikimedia Commons**: 퍼블릭 도메인에 자주 있다
5. **AI 생성 방어선**(nano-banana-pro): 실제 제품 사진을 참고로 AI에 넘겨 애니메이션 장면에 맞는 변형을 생성하게 한다. **CSS/SVG로 손으로 그려 대체하지 말 것**

```bash
# 예: DJI 공식 사이트 제품 hero image 다운로드
curl -A "Mozilla/5.0" -L "<hero-image-url>" -o assets/<brand>-brand/product-hero.png
```

**3.3 UI 스크린샷 (디지털 제품 필수)**

- App Store / Google Play의 제품 스크린샷(주의: 실제 UI가 아니라 mockup일 수 있으니 대조할 것)
- 공식 사이트 screenshots section
- 제품 데모 영상 프레임 캡처
- 제품 공식 Twitter/X의 출시 스크린샷(대개 최신 버전이다)
- 사용자에게 계정이 있으면 실제 제품 화면을 직접 캡처

**3.4 · 소재 품질 기준선 「5-10-2-8」 원칙 (철칙)**

> **Logo의 규칙은 다른 소재와 다르다.** Logo는 있으면 반드시 쓴다(없으면 멈춰서 사용자에게 묻는다). 다른 소재(제품 사진/UI/참고 이미지/삽화)는 「5-10-2-8」 품질 기준선을 따른다.
>
> 2026-04-20 Neo의 원문: 「우리 원칙은 5라운드 검색해서 소재 10개를 찾고 그중 좋은 2개를 고르는 것이다. 각각 8/10점 이상이어야 한다. 과제를 끝내려고 머릿수를 채우기보다 적은 편이 낫다.」

| 항목 | 기준 | 안티패턴 |
|---|---|---|
| **5라운드 검색** | 여러 채널을 교차 검색한다(공식 사이트 / press kit / 공식 SNS / YouTube 프레임 캡처 / Wikimedia / 사용자 계정 화면 캡처). 한 라운드 돌려 앞의 2개 집고 멈추는 게 아니다 | 첫 페이지 결과를 그대로 쓴다 |
| **후보 10개** | 최소 10개를 모아 놓고 걸러내기를 시작한다 | 2개만 받아 와서 고를 게 없다 |
| **좋은 2개를 고른다** | 10개 중에서 최종 소재 2개를 정선한다 | 다 쓴다 = 시각 과부하 + 취향 희석 |
| **각각 8/10점 이상** | 8점에 못 미치면 **쓰지 않는 편이 낫다.** 정직한 placeholder(회색 블록 + 텍스트 라벨)나 AI 생성(nano-banana-pro로 공식 참고를 바탕에 두고)을 쓴다 | 머릿수 채우려고 7점 소재를 brand-spec.md에 넣는다 |

**8/10 채점 항목**(채점 시 `brand-spec.md`에 기록한다):

1. **해상도** · 2000px 이상(인쇄/대형 화면 장면은 3000px 이상)
2. **저작권 명확성** · 공식 출처 > 퍼블릭 도메인 > 무료 소재 > 도용 의심(도용 의심은 바로 0점)
3. **브랜드 기질과의 부합도** · brand-spec.md의 「기질 키워드」와 일치할 것
4. **광선/구도/스타일 일관성** · 소재 2개를 나란히 놓아도 서로 싸우지 않을 것
5. **독립적 서사 능력** · 하나만으로 서사 역할을 표현할 수 있을 것(장식이 아니다)

**이 기준선이 철칙인 이유**:
- Neo의 철학: **모자란 편이 넘치는 편보다 낫다.** 머릿수를 채운 소재는 없는 것보다 나쁘다 — 시각 취향을 오염시키고 「비전문」 신호를 전달한다
- **「디테일 하나를 120%로, 나머지를 80%로」의 정량판**: 8점은 "나머지 80%"의 하한선이고, 진짜 hero 소재는 9-10점이어야 한다
- 소비자가 작품을 볼 때 모든 시각 요소가 **점수를 더하거나 깎는다.** 7점 소재 = 감점 항목이고, 비워 두는 편이 낫다

**Logo 예외**(재확인): 있으면 반드시 쓰고, 「5-10-2-8」을 적용하지 않는다. logo는 「여럿 중 하나 고르기」 문제가 아니라 「식별도의 뿌리」 문제이기 때문이다 — logo 자체가 6점밖에 안 되더라도 logo가 없는 것보다 10배 낫다.

##### Step 4 · 검증 + 추출 (색값 grep이 전부가 아니다)

| 자산 | 검증 동작 |
|---|---|
| **Logo** | 파일 존재 + SVG/PNG가 열림 + 최소 두 가지 버전(어두운 바닥/밝은 바닥용) + 투명 배경 |
| **제품 사진** | 최소 한 장이 2000px 이상 + 배경 제거 또는 깨끗한 배경 + 여러 각도(주 시점, 디테일, 장면) |
| **UI 스크린샷** | 해상도가 실물 그대로(1x / 2x) + 최신 버전(구버전이 아님) + 사용자 데이터 오염 없음 |
| **색값** | `grep -hoE '#[0-9A-Fa-f]{6}' assets/<brand>-brand/*.{svg,html,css} \| sort \| uniq -c \| sort -rn \| head -20`으로 뽑고 흑백회색은 걸러낸다 |

**시연용 브랜드 오염을 경계한다**: 제품 스크린샷에는 사용자 demo의 브랜드 색이 섞여 있기 마련이다(어떤 도구의 스크린샷이 헤이티 레드로 시연하는 식). 그건 그 도구의 색이 아니다. **강한 색 두 가지가 동시에 나타나면 반드시 구분해야 한다.**

**브랜드는 여러 단면을 갖는다**: 같은 브랜드의 공식 사이트 마케팅 색과 제품 UI 색이 다른 경우가 많다(Lovart 공식 사이트는 따뜻한 아이보리 + 오렌지, 제품 UI는 Charcoal + Lime). **둘 다 진짜다** — 납품 장면에 맞는 단면을 고른다.

##### Step 5 ·`brand-spec.md` 파일로 고정 (템플릿이 모든 자산을 덮어야 한다)

```markdown
# <Brand> · Brand Spec
> 수집 일자: YYYY-MM-DD

**spec을 다 쓴 뒤의 실행 규율(하드 요구)**:
- 모든 HTML은 `brand-spec.md`에 적힌 자산 파일 경로를 **참조해야** 한다. CSS 실루엣이나 손으로 그린 SVG로 대체하는 것은 허용되지 않는다
- Logo는 `<img>`로 실제 파일을 참조하고 다시 그리지 않는다
- 제품 사진도 `<img>`로 실제 파일을 참조하고 CSS 실루엣으로 대체하지 않는다
- CSS 변수는 spec에서 주입한다: `:root { --brand-primary: ...; }`. HTML은 `var(--brand-*)`만 쓴다
- 이렇게 하면 브랜드 일관성이 「자각에 의존」에서 「구조에 의존」으로 바뀐다 — 색을 임시로 추가하려면 먼저 spec을 고쳐야 한다

##### 전 과정이 실패했을 때의 방어선

자산 유형별로 처리한다.

| 없는 것 | 처리 |
|---|---|
| **Logo를 전혀 못 찾음** | **멈추고 사용자에게 묻는다.** 억지로 진행하지 말 것(logo는 브랜드 식별도의 뿌리다) |
| **제품 사진(실물 제품)을 못 찾음** | nano-banana-pro AI 생성 우선(공식 참고 이미지를 바탕에 두고) → 다음으로 사용자에게 요청 → 마지막이 정직한 placeholder(회색 블록 + 텍스트 라벨, "제품 사진 보완 예정"을 명확히 표기) |
| **UI 스크린샷(디지털 제품)을 못 찾음** | 사용자 본인 계정의 화면 캡처를 요청 → 공식 데모 영상 프레임 캡처. mockup 생성기로 머릿수를 채우지 않는다 |
| **색값을 전혀 못 찾음** | 「디자인 방향 어드바이저 모드」로 가서 사용자에게 3개 방향을 제안하고 assumption을 표기한다 |

**금지**: 자산을 못 찾았다고 조용히 CSS 실루엣이나 범용 그라디언트로 밀어붙이기 — 이 프로토콜의 가장 큰 안티패턴이다. **멈춰서 묻는 편이 낫고, 머릿수를 채우지 않는다.**

##### 반례 (실제로 밟은 함정)

- **Kimi 애니메이션**: 기억에 의존해 「오렌지겠지」 추측했는데 실제 Kimi는 `#1783FF` 파란색 — 한 번 재작업
- **Lovart 디자인**: 제품 스크린샷에서 시연용 브랜드였던 헤이티 레드를 Lovart 자신의 색으로 착각 — 디자인 전체를 망칠 뻔했다
- **DJI Pocket 4 출시 애니메이션(2026-04-20, 이 프로토콜 승격을 촉발한 실제 사례)**: 색값만 뽑는 구판 프로토콜로 진행해 DJI logo를 받지 않고 Pocket 4 제품 사진도 찾지 않고 CSS 실루엣으로 제품을 대체했다 — 결과는 「범용 검은 바닥 + 오렌지 accent 테크 애니메이션」이고 DJI 식별도가 없었다. Neo의 원문: 「그러지 않으면 우리는 대체 무엇을 표현하고 있는 건가?」 → 프로토콜 승격.
- 색을 뽑아 놓고 brand-spec.md에 적지 않아서 세 번째 페이지에서 주색 수치를 잊고, 그 자리에서 「가깝지만 다른」 hex를 넣었다 — 브랜드 일관성 붕괴
- **5대 Coding Agent 비교 PPT(2026-06-06, 발동 조건 확장을 촉발한 실제 사례)**: agent가 작업을 「PPT + 스타일 참고 없음」으로 판단해 Fallback 디자인 방향 어드바이저로 갔고, 다섯 회사의 브랜드 색만 뽑아 세 가지 디자인 논리를 spawn했다. **다섯 제품 logo(Claude Code / Cursor / Codex / Copilot / Trae)를 하나도 가져오지 않았다** — Neo에게 현장에서 「왜 이 제품들의 logo를 가져오지 않았나」로 잡혔다. 근본 원인: 「비교 / 순위 deck」을 §1.a 미발동으로 오판했고(§1.a가 「단일 고객사용 제작물」만 담당한다고 여겼다), Fallback 경로에 logo 체크포인트가 하나도 없었다. → 수정: ① 발동 조건을 두 종류로 확장(「디자인에서 실제 제품을 지목/병렬 배치」 포함) ② Fallback도 logo 수집을 면제하지 않음 ③ Phase 3.5에 「지명 제품 logo 서브 게이트」를 추가해 spawn 전에 반드시 통과 ④ Step 3.1에 svgl/simpleicons/Google favicon 신뢰 가능한 수집 경로 보강.

##### 프로토콜 비용 vs 하지 않은 비용

| 장면 | 시간 |
|---|---|
| 프로토콜을 제대로 완주 | logo 다운로드 5 min + 제품 사진/UI 3-5장 다운로드 10 min + 색값 grep 5 min + spec 작성 10 min = **30분** |
| 프로토콜을 하지 않은 비용 | 식별도 없는 범용 애니메이션이 나옴 → 사용자 재작업 1-2시간, 심하면 전면 재제작 |

**안정성에 대한 가장 값싼 투자다.** 특히 상업 발주/발표회/중요 고객 프로젝트에서 30분의 자산 프로토콜은 목숨값이다.
