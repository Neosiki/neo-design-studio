# NeoDesign 선택형 웹툰 · 4컷

웹툰과 4컷만화를 요청했을 때만 이 경로를 쓴다. 부모 스킬의 삼방향 선택 절차와 사실 확인 원칙(#0)은 그대로 적용한다.
컷별 규칙, spec 필드, 매장 홍보 구성표, 납품 전 점검표는 [웹툰 레시피](references/webtoon-recipes.md)에 있다. 명령은 저장소 루트 기준이다.

## 경로와 범위

- 이 스킬이 하는 일은 다섯 가지다: 콘티 작성, 컷 그림 마련, 컷별 이미지 프롬프트 2안 만들기(외부 도구용), 컷 그림에 말풍선·효과음·해설·실제 로고를 올리기, 4컷 이미지나 세로 스크롤 이미지로 묶어 내보내기.
- 컷 그림은 세 경로 중 컷마다 고른다. 섞어 써도 된다.
  - Claude가 직접 그린다(art 경로): Claude가 컷마다 SVG를 쓰고 스크립트가 PNG로 렌더한다. ChatGPT·Gemini 같은 외부 도구나 계정이 필요 없다. 둥근 마스코트, 사물, 음식, 배경, 단순한 인물에 맞고, 사실적인 인물·손·제품 사진 질감은 맡지 못한다.
  - 외부 도구로 만든 파일을 받는다: `prompts`가 컷별 프롬프트 2안을 주고, 완성 파일을 `image`에 연결한다.
  - 사용자가 가진 그림·사진을 `image`에 연결한다.
- 사용자가 경로를 말하지 않았으면 인물이 사실적이어야 하는지부터 판단한다. 마스코트·사물 중심이면 art 경로를 기본으로 제안하고, 사실적 인물이나 사진 질감이 필요하면 외부 도구 경로를 안내한다.
- 세 가지 모드 중 하나를 먼저 정한다. 사용자가 말하지 않았으면 한 번만 묻는다.
  - 매장 홍보형: SNS용 4컷(정사각 1:1 또는 4:5). 메뉴 소개·이벤트 안내·후기 소개 시작 틀이 있다.
  - 에피소드형: 10~30컷 세로 스크롤 한 회차. 콘티, 컷 리듬, 페이지 분할까지 다룬다.
  - 4컷 전용: 콘티, 프롬프트 2안, 말풍선, 합성만 한다. 형식은 정사각·4:5·세로 띠 중에서 고른다.
- 신규 웹툰도 새로운 시각 디자인이다. 삼방향 초안은 「화풍 한 줄 + 캐릭터 앵커 문장 + 팔레트 + 샘플 컷 프롬프트 한 장」으로 구성해 사용자가 고르게 한다. 그림 생성 도구가 있으면 샘플 컷을 실제로 만들어 보이고, 없으면 프롬프트만 제시한다. 이미 승인한 방향이 있으면 다시 묻지 않는다.
- 매장 간판·상호·로고·메뉴판·실제 사진은 생성 이미지로 대신하지 않는다. 대표가 준 파일을 `overlays`로 합성한다. 파일이 없으면 자리표시로 두고 보완을 요청한다(부모 스킬 §1.a).
- 실존 인물이나 기존 만화 캐릭터를 닮게 그리라는 요청은 받지 않는다. 캐릭터는 이 작업을 위한 새 인물로 설계한다.
- 연재 플랫폼 업로드와 예약 발행은 범위 밖이다. 이미지 파일까지 만든다.

## 작업 순서

1. 목적을 확정한다: 모드, 독자, 게시 채널, 컷 수, 한 줄 메시지. 매장 홍보형이면 이벤트 기간·가격·영업시간·후기 원문을 대표가 확인한 자료로만 받는다. 가격·기간·수치·후기는 지어내지 않는다.
2. 사실 확인: 특정 제품·행사·법규를 다루면 부모 스킬 핵심 원칙 #0대로 먼저 검색한다. 확인한 사실은 `product-facts.md`에 적는다.
3. 시작 spec을 만든다: `node skills/webtoon-studio/scripts/webtoon-studio.mjs init --kind four-cut|episode|store-menu|store-event|store-review --out spec.json`. 캐릭터는 `characters[].anchor`에 나이대·머리·옷·소품을 구체적으로 적는다. 이 문장이 모든 컷 프롬프트 맨 앞에 그대로 붙어 컷마다 같은 인물로 보이게 한다.
4. 콘티를 쓴다: 컷마다 `scene`(무슨 일이 일어나는가), `shot`(넓은 샷·중간 샷·클로즈업), `bubbles`(대사)를 채운다. 한 컷에는 사건 하나, 말풍선은 3개 이하다. 4컷은 도입·전개·전환·마무리, 에피소드는 훅 → 전개 → 전환 → 여운 순서다(레시피 참고). 콘티는 사용자에게 보여 주고 승인받은 뒤 그림 단계로 간다.
5. 검사: `... check --spec spec.json`. 오류는 반드시 해소하고, 경고는 읽고 판단한다. 가격·날짜 같은 수치는 「대표 확인 자료와 대조할 수치·날짜」 목록으로 따로 나온다.
6. 컷 그림을 마련한다.
   - Claude가 그리는 경우: `... art-size --spec spec.json`으로 컷별 캔버스 크기를 확인하고, `... art-init --spec spec.json --out-dir art --link`로 컷별 SVG 뼈대를 만든다. 뼈대의 주석에 장면·구도·캐릭터 앵커·사용할 수 있는 공용 정의(그라데이션, 번짐, 얼굴 `wt-face-*`)가 적혀 있다. 컷마다 SVG를 채우고 `... art --spec spec.json --out-dir _art --guides`로 렌더해 PNG를 직접 눈으로 본다(말풍선 자리는 빨간 점선). 겹침·잘림·캐릭터 불일치를 고쳐 두 번까지 다시 그린다. 세부는 레시피 §9.
   - 외부 도구를 쓰는 경우: `... prompts --spec spec.json --out prompts.md`. 컷마다 A안(안정형)과 B안(변주형)이 나온다. 둘 다 만들어 더 나은 쪽을 고르고, 말풍선 자리가 비어 있고 그림 안에 글자가 없는지 확인한 뒤 `panels[].image`에 연결한다.
7. 그림이 일부 없으면 `--allow-placeholder`로 레이아웃만 리허설할 수 있다. 납품본에는 자리표시가 한 컷도 남으면 안 된다.
8. 합성: `... compose --spec spec.json --out-dir _webtoon`(art 컷은 이 단계에서 자동으로 렌더된다). 4컷은 `fourcut-1x1.png` 또는 `fourcut-4x5.png`, 세로 스크롤은 `full.png`와 컷 경계에서만 자른 `page-01.png`…이 나온다. `manifest.json`에 크기·경고·대조 수치가 남는다.
9. 납품 전 `references/webtoon-recipes.md`의 점검표를 거친다. 휴대폰 폭(약 400px)으로 줄여 대사가 읽히는지, 같은 인물이 컷마다 같은지, 수치가 확인 자료와 일치하는지를 눈으로 본다.

## 환경

Node 18 이상과 Playwright(Chromium)가 필요하다(`npm i playwright`, `npx playwright install chromium`). `init`·`check`·`prompts`·`art-size`·`art-init`은 브라우저 없이 돌고, `art`(SVG 렌더)와 `compose`는 브라우저를 쓴다. 글꼴은 시스템의 Noto Sans CJK KR, Malgun Gothic, Apple SD Gothic Neo 순으로 쓰고, 다른 글꼴은 spec의 `fontFile`에 파일 경로를 준다. 상업 이용이 가능한 글꼴인지 확인한다. 네트워크를 쓰지 않는다.
