# 품질 게이트 — 항목별 근거

> `design check`가 내는 판정 하나하나가 무엇에 근거하는지. 앞 단계: [`DESIGN_CLI_KO.md`](./DESIGN_CLI_KO.md)

## 이 문서가 있는 이유

검사기는 "이건 틀렸다"고 말하는 물건이다. 그러니 **왜 틀렸는지 댈 수 있어야 한다.** 근거가 없는 판정은 취향의 강요이고, 사람은 취향을 강요하는 도구를 곧 끈다.

그래서 조판·크기 판정의 기준값은 전부 이 저장소가 이미 가지고 있던 문서에서 가져왔다.

| 기준 | 출처 |
|---|---|
| 행장·행간·자간, 중서 혼합, 글꼴 배합 | `references/typography.md` |
| 매체별 최소·표준 크기, 대비, 남용 글꼴 | `references/content-guidelines.md` |
| 자산 출처·라이선스 | `references/brand-asset-protocol.md` |
| 삼방향·승인 절차 | `references/workflow.md` · `references/verification.md` |

판정문에는 근거 위치가 함께 들어간다. 사람이 "왜?"라고 물을 필요가 없어야 한다.

## 조판 (`typography`)

### 글꼴 사슬

| 검사 | 수준 | 근거 |
|---|---|---|
| `type.genericFallback` | 경고 | 사슬이 총칭 계열로 끝나지 않으면 "글꼴이 하나도 없을 때"의 모습이 정의되지 않는다 |
| `type.systemOnly` | 경고 | `sans-serif` 하나면 윈도우는 맑은 고딕, macOS는 애플 SD 고딕 — 같은 페이지가 기기마다 다른 얼굴이 된다 (typography.md 5장) |
| `type.cjkFallback` | 경고 | 한글·한자가 쓰이는데 사슬에 CJK 자형이 없으면 시스템 기본으로 떨어진다 |
| `type.latinFirst` | 경고 | `font-family`는 글자 단위로 맞춰 나간다. CJK 글꼴이 앞에 있으면 라틴 문자와 숫자를 그쪽이 먼저 가져가고, 뒤의 서양 글꼴은 출전 기회가 없다 (typography.md 4.2) |
| `type.overusedFont` | 경고 | Inter·Fraunces·Space Grotesk·Playfair Display를 display에 쓰는 것 (typography.md 3장 「이미 과도하게 사용된 목록」) |

`type.overusedFont`는 **display 자리에서만** 걸린다. Inter를 14-16px 본문에 쓰는 것은 정확한 용법이고, 문서도 그렇게 적었다.

CJK 규칙은 선언한 `brief.language`가 아니라 **실제로 산출물에 적힌 글자**로 켜진다. `lang`이 잘못 적혀 있어도 한글이 시스템 기본으로 떨어지는 사고는 똑같이 일어나기 때문이다.

### 음계

| 검사 | 수준 | 근거 |
|---|---|---|
| `type.scaleSteps` | 경고 | 7단을 넘으면 층위가 많을수록 각 층위의 값이 떨어진다 (typography.md 1장·5장) |
| `type.scaleRatio` | 경고 | 인접 비율의 최대/최소가 2.2배를 넘으면 고정 비율을 곱해 만든 음계가 아니라 눈대중으로 고른 숫자 목록이다 |

### 블록

| 검사 | 수준 | 근거 |
|---|---|---|
| `type.weightSynthesis` | 경고 | 토큰이 싣지 않은 굵기. 렌더러가 `font-synthesis: none`을 켜므로 이 강조는 화면에 **나타나지 않는다** (typography.md 4.3) |
| `type.tracking` | 오류/경고 | 한글·한자에 음수 자간. 네모틀 글자는 자면이 꽉 차 있어 음수 자간이 곧 획 충돌이다. 대자에서 -0.02em이 한계 (typography.md 4.5) |
| `type.lineHeight` | 경고 | 언어·크기별 권장 구간 밖. 한글은 서문보다 0.2 정도 높다 (typography.md 2장) |
| `type.measure` | 경고 | 한 줄 글자수. 한글 22~38자, 서문 45~75자 (typography.md 2장) |
| `type.headingSize` | 경고 | 발표 슬라이드 제목 60~120px (content-guidelines.md Scale 규범) |
| `type.quotes` | 경고 | 곧은 따옴표는 타자기의 흔적이다. `code` 블록은 제외 |

### "큰 글자"는 픽셀이 아니라 비율로 정한다

같은 36px가 웹에서는 표제고 슬라이드에서는 본문이다. 그래서 매체별 표준 본문 크기(웹 17 · 덱 30 · 영상 36)를 두고, 그 **2.2배를 넘으면 대자**로 본다. 이 기준 하나가 없으면 슬라이드의 36px 불릿과 웹의 36px 표제를 똑같이 판정하게 된다.

기준값은 `scripts/design/lib/render/shared.mjs` **한 곳**에 있다. 렌더러가 CSS로 쓰고, 검사기가 판정에 쓰고, 넘침 추정도 같은 값을 쓴다. 세 곳에 따로 적으면 "검수는 통과했는데 화면은 틀린" 상태가 만들어지고, 그건 검사가 없는 것보다 나쁘다. `tests/quality.mjs`가 렌더 결과의 실제 `line-height`를 읽어 이 일치를 붙잡아 둔다.

### 검사하지 않는 것

- **금칙 처리**(줄 첫머리 마침표) — IR만으로는 줄바꿈 위치를 알 수 없다. 렌더러가 `line-break: strict`를 내보내고, 검사는 그 선언이 실제로 나가는지만 확인한다.
- **표점 압축**(`halt`·`palt`) — 실제 글꼴의 지원 여부에 달려 있어 파일만 보고 판정할 수 없다.
- **글꼴 파일의 실제 굵기 목록** — 토큰의 선언을 계약으로 본다. 선언이 곧 어떤 파일을 싣는지의 결정이기 때문이다.

## 접근성 (`a11y`)

| 검사 | 수준 | 근거 |
|---|---|---|
| `a11y.lang` | 오류 | 언어 선언 없음. `<html lang>`이 비면 낭독기가 발음 규칙을 정하지 못한다 |
| `a11y.langMismatch` | 경고 | 선언한 언어와 실제 글자가 다름. `lang="en"`에 한글이 있으면 낭독기가 한글을 영어 발음으로 읽으려 든다 |
| `a11y.altQuality` | 경고 | 대체 텍스트가 '이미지'·'로고'처럼 종류만 말하거나, 파일 이름이거나, 200자를 넘음 |
| `a11y.decorativeAlt` | 경고 | 장식 도형에 붙은 대체 텍스트. 낭독기가 의미 없는 말을 읽는다 |
| `a11y.headingMissing` | 경고 | 본문은 있는데 제목이 없음. 낭독기 사용자는 제목 목록으로 문서를 훑는다 |
| `a11y.headingOrder` | 경고 | h2가 h1보다 먼저 나오거나, 한 화면에 h1이 여럿 |
| `a11y.readingOrder` | 경고 | 시각 순서와 배열 순서 불일치. 절대 배치에서는 배열 순서가 곧 낭독·탭 순서다 |
| `a11y.captions` | 오류 | 보이스오버가 있는데 자막이 없음. 소리에만 담긴 정보는 듣지 못하는 사람에게 존재하지 않는다 |
| `a11y.subtitleRate` | 경고 | 자막 속도 상한 — 한글·한자 초당 9자, 서문 20자 |
| `a11y.motion` | 경고 | `expressive` + 800ms 초과. 렌더러가 `prefers-reduced-motion`을 처리하지만, 정보가 움직임에만 담기면 그 사용자에게는 정보가 사라진다 |

`brief.language`의 **형식**(BCP 47)은 스키마가 이미 강제한다. 검사기가 같은 것을 한 번 더 말하면 보고서만 길어진다. 그래서 `a11y`는 스키마가 볼 수 없는 것 — 선언과 내용의 일치 — 만 본다.

### 검사하지 않는 것

- **클릭 대상 44×44px** — IR에 링크·버튼 종류가 없다. 없는 것을 검사하는 척하지 않는다. 상호작용 블록이 생기면 그때 넣는다.
- **낭독기의 실제 낭독 결과** — DOM 순서로 근사할 뿐이다. 여기서는 그 DOM 순서가 화면 순서와 어긋나는 경우만 잡는다.

## 보안 (`security`)

디자인 도구가 왜 비밀을 검사하나 — 이 저장소의 산출물은 **배포되는 파일**이기 때문이다. 매니페스트의 문자열은 렌더 결과에 그대로 들어가고, HTML은 사람에게 보내진다. 스크린샷에 키가 찍히는 사고는 커밋에 키가 들어가는 사고만큼 흔하다.

| 검사 | 수준 | 무엇을 |
|---|---|---|
| `secret.key` | 오류 | 매니페스트·IR 안의 OpenAI · Anthropic · GitHub · GitLab · AWS · Google · Slack · npm 토큰, JWT, 개인 키 |
| `secret.output` | 오류 | **산출물 파일** 안의 같은 값들. 원본에는 없고 산출물에만 있는 경우가 실제로 있다 (인라인된 자산, 붙여 넣은 설정) |
| `secret.file` | 오류 | `.env` · `.pem` · `id_rsa` · `credentials.json` 류를 자산으로 등록 |
| `secret.homePath` | 경고 | `C:\Users\<이름>` · `/Users/<이름>` 절대 경로 |
| `secret.privateHost` | 경고 | `localhost` · 사설 대역 · `*.internal` 주소 |

**형태로 확신할 수 있는 것만 오류로 올린다.** 엔트로피 추정으로 "비밀 같다"고 말하기 시작하면 sha256 해시, base64 이미지, 긴 색상표가 전부 걸려 아무도 보고서를 읽지 않는다. 발급 기관이 접두어를 고정해 둔 것들만 모은 이유다.

보고서는 찾은 값을 **가려서** 적는다(`AKIAIOSF…LE (20자)`). 보고서가 두 번째 유출이 되면 안 된다. `/home/runner` 같은 공용 CI 계정은 개인 경로로 보지 않는다 — 모든 CI 실행이 노랗게 물들면 경고의 뜻이 사라진다.

## 오탐을 대하는 태도

검사기가 죽는 방식은 두 가지고, **놓치는 쪽보다 잘못 잡는 쪽이 훨씬 빨리 죽는다.** 경고가 늘 켜져 있으면 사람은 보고서를 통째로 무시하기 시작하고, 그 순간 진짜 오류도 함께 묻힌다.

그래서 `tests/quality.mjs`는 "잡는다"가 아니라 **"멀쩡한 것을 잡지 않는다"** 쪽을 증명한다.

- 제대로 선 폴백 사슬에는 아무 말도 하지 않는다
- 한글 프로젝트 안의 영문 인용은 서문 기준으로 본다
- 한 줄에 다 들어가는 문장에는 행장 판정을 하지 않는다
- `code` 블록의 곧은 따옴표는 조판 문제가 아니다
- sha256 해시·base64 이미지를 비밀로 착각하지 않는다
- 같은 행에 나란히 놓인 블록은 좌→우가 정상 순서다

## 새 검사를 추가할 때

1. 근거를 댄다. `references/` 안의 문서를 가리킬 수 없으면 넣지 않는다.
2. `tests/fixtures/failing-project`에 트리거 사례를 넣고 `tests/run.mjs`의 `MUST_CATCH`에 id를 등록한다.
3. `tests/quality.mjs`에 **오탐하지 않는다**는 사례를 함께 넣는다.
4. 두 예제(`examples/`)가 여전히 경고 0으로 통과하는지 확인한다. 통과하지 못하면 검사가 틀렸거나 예제가 틀렸다 — 어느 쪽인지 판단해서 고친다.
5. 판정문에 근거 위치를 적는다. 사람이 "왜?"라고 되물을 필요가 없어야 한다.
